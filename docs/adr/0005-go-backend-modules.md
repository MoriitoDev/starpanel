# Two Go modules under internal, transport in main

The backend grew as a single `package main`: the route table in one file and its handlers in five, and the stored-document invariant enforced once in the handler and again inside the store. It is now three packages — `internal/dashboard` (the Dashboard document, its store, and the rule that what comes back out is migrated, normalised and valid) and `internal/plugins` (Manifest, folder discovery, the supervised backends, and the seam that hides subprocesses behind an `http.Handler`) — with `main` as the composition root and the whole HTTP surface in `server.go` behind `newServer(deps)`. Rejected: keeping one package with tidier files, because nothing would stop the seams blurring again when any file may call any other; and one package per concern, because `stats`, the folder rule and the transport are not big enough to earn one — a package whose interface is as wide as its implementation is shallow, not deep.
